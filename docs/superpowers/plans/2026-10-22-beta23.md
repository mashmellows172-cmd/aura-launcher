# Aura Beta23 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax.

**Goal:** Polish Aura's themed home and editor while closing measurable daily-use regressions.
**Architecture:** Shared pure layout policy feeds home and preview; one themed card renders both. Existing preference stores and saved draft remain authoritative.
**Tech Stack:** Existing Kotlin 2.2.10/Compose, AGP9.2.1, API29–37, JDK17, JUnit4, ADB/UIAutomator.
**Spec:** docs/superpowers/specs/2026-10-22-beta23-design.md

## Global Constraints

- Keep package/signing, preferences, avatar, widgets and all theme layouts. Nothing stays default.
- No new permissions, dependency upgrades or network service. Repeated weather motion requires explicit opt-in and visible lifecycle.
- Personal manufacturer resources stay optional and outside source/APK.
- Platform 48dp controls; half width only at least 280dp and font scale at most 1.5.
- Operational quota cutoff 90–92%; never deliberately exceed 95% in either account window.

## Review Focus

- Large text/narrow preview uses the same full-width fallback as home.
- Draft selection, undo and cancellation survive activity recreation without writes.
- Missing provider/library or denied calendar permission retains useful action/empty states.
- Every actual theme's text/surface colors remain readable, including normal icons and high contrast.
- Phone settings changed for QA restore after failures; uncontrolled device samples never establish causal speed gains.
